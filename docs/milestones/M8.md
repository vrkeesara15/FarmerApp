## How the natural-language questions are kept safe
Four independent layers, any one of which would stop a bad query.

1. The query runs as a role that may read five views and nothing else, and cannot write anywhere.
2. The transaction is read-only with a statement timeout, inside a savepoint that is always rolled back.
3. Every view filters on the caller's tenant and calls a scope function, so a cluster head sees only their own cluster whatever query the model wrote.
4. A validator runs first: one select, allowlisted relations and functions, no schema or data changes, no system catalogues.

The model is shown column names and descriptions only, never a row and never a value. A question carrying a phone number is refused before it is sent.

**Second tenant onboarded in under 30 minutes**: the automated path is proven. A test walks
create, invite, one-time-password login, branding, store, officer, farmer and visit entirely
through the API in 491 milliseconds, with no manual step and no code that knows the tenant's
name. The 30 minutes is the human budget around that half-second and still needs one timed

## Decisions and human gates
Plan prices are engineering placeholders tied to the cost envelope, not commercial decisions.
Referral reward amounts are zero placeholders. The payment provider, the tax treatment of the
platform fee and the dunning policy are all listed in the tenant administration change. The
iOS build needs an Apple developer account, Xcode and signing. Everything else carried
forward is in `docs/decisions-pending-owner.md`.
