## What changed

- **Model + migration** `apps/api/farmerapp/db/models/audit_log.py`, `apps/api/alembic/versions/0004_audit_log.py`: `audit_log(id, tenant_id, created_at, actor_id NULL=system, actor_role, action "<entity>.<verb>", entity = table name, entity_id uuid, before jsonb, after jsonb, ip, device_id, user_agent, trace_id)` on a new lean `TenantRow` mixin (`apps/api/farmerapp/db/base.py`; no `updated_at`/`deleted_at`/`version` because rows never change). RLS like every table (`enable_rls("audit_log", append_only=True)`) and **append-only for the app role**: SELECT + INSERT granted, UPDATE/DELETE/TRUNCATE revoked. Indexes `(tenant_id, entity, entity_id, created_at DESC)` and `(tenant_id, created_at, id)`. Backward compatible (one new table). Downgrade drops it.
- **Mechanism** `apps/api/farmerapp/db/audit.py`:
  - `Actor` in a `ContextVar`: `get_current_user` binds `actor_from_request(request, user)` (ip = first `X-Forwarded-For` hop or the peer, device = `X-Device-Id` header else the user's bound device, `User-Agent`, structlog `trace_id`); `TraceMiddleware` clears it per request; jobs/worker use `actor_scope(system_actor(tenant_id))` (the seed does). No context → `actor_id` NULL, `actor_role` `system`.
  - `before_flush` listener on every `Session` (installed at import of `farmerapp.db.models` / `farmerapp.db.audit`, and by `get_session_factory`): every `new`/`dirty`/`deleted` object with a `tenant_id` gets an `AuditLog` in the **same flush** → commits or rolls back with the mutation. Create: `before` NULL, `after` = row; update: only changed columns + `id`; setting `deleted_at` → `<entity>.delete`; `session.delete` → `<entity>.delete` with `after` NULL. `__audit__ = False` opts a model out (`AuditLog` itself).
  - Redaction in one place: `REDACTED_COLUMNS = {code_hash, token_hash}` never recorded, `MASKED_COLUMNS = {phone: last 4 digits}`, `EXCLUDED_COLUMNS = {updated_at, version}`. `created_at` is the wall clock (not the transaction's `now()`) so rows within one request keep their order.
  - `audit.record(session, action=, entity=, entity_id=, tenant_id=, before=, after=, actor=)` for non-row events.
- **Auth events** `apps/api/farmerapp/auth/router.py`, `tokens.py`: OTP verify success binds the user as actor (so the refresh-token insert and device binding are attributed to them) and records `auth.login` (`after = {device_id, channel}`); logout records `auth.logout` (`after = {family_id, device_id}`; `TokenService.revoke` now returns the row). Failed OTPs write no login row (their attempt counters are `otp_challenge.update` rows — a useful trail of failed attempts).
- **Read endpoint** `apps/api/farmerapp/audit/` `GET /v1/audit-logs` (owner, director, auditor, tenant_admin; `x-roles` in `openapi.yaml` → SEC-006 matrix covers it): filters `entity`, `entity_id`, `actor_id`, `action`, `from`, `to`; newest first with cursor pagination (`PageRequest.before(...)` added to `api/pagination.py`).
- **Retention job** `apps/api/farmerapp/jobs/purge_audit_logs.py` + `python -m farmerapp.jobs purge-audit-logs --tenant-id … [--older-than-days 400]`: dry run only — counts and logs (`audit_purge_dry_run`) rows past the window, refuses windows under 365 days, deletes nothing (the app role cannot).
- **RLS meta-check** `apps/api/farmerapp/db/rls.py`: `APPEND_ONLY_TABLES`, `rls_statements(..., append_only=)`, `rls_violations` now requires SELECT+INSERT everywhere and *rejects* UPDATE/DELETE on append-only tables.
- **App wiring**: `X-Device-Id` in CORS allow-headers; `farmerapp.api.app` imports the models package; `openapi.yaml` regenerated; `apps/api/README.md` "Audit trail" section; progress rows.

Design decisions and assumptions:
- Audit rows live in the tenant's own RLS scope: an owner/auditor sees their trail through the API, nobody sees another tenant's. Append-only is enforced by grants (not policy), so a compromised app credential cannot rewrite history.
- Auth tables (`otp_challenge`, `refresh_token`) *are* audited (hence the hash redaction) — they are mutations too and give a login-attempt trail for free; OTP send/attempt rows before the user is known are attributed to the system.
- High-volume telemetry tables (raw location points, M2) should set `__audit__ = False`; the location policy (VV-*) audits at the visit level instead.
- `X-Forwarded-For` is trusted only for its first hop (what the Cloud Run load balancer sets); locally it is the socket peer.
- Real purge/archival is deferred to OPS / NF-012 (needs the migrate role and the exports bucket); the 400-day default leaves a margin over the one-year minimum.
