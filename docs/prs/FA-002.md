## What changed

- **Policy registry** `apps/api/farmerapp/auth/policy.py`: `Role` (the ten FA-002 roles, same enum as the `user.role` column), `require_roles(*roles, self_param=None)` — a FastAPI dependency that authenticates (`get_current_user`) and returns the `User` when the role is allowed, or when `self_param` names a path parameter equal to the caller's id; `PUBLIC` marker for token-less routes. `install_policies(app)` runs in `create_app`: it walks every `APIRoute` (nested routers flattened via `fastapi.routing.iter_route_contexts`), raises `RuntimeError` naming any route without a policy or with conflicting ones, keeps the registry on `app.state.policies`, and post-processes the OpenAPI document so every operation carries `x-roles: [...]` (plus `x-self: <param>`) or `x-public: true`, and every protected operation documents `401` (`unauthenticated`, `token_expired`, `user_disabled`) and `403` (`forbidden`). Denied calls answer RFC 9457 `403 forbidden` and log WARNING `authz_forbidden` with `actor_id`, `role`, `tenant_id`, `method`, `route` (template) — no phone or name.
- **Scope helper** `apps/api/farmerapp/auth/scope.py`: SPEC 2.6 as data (`DEFAULT_VISIBILITY`: tenant-wide for owner/director/tenant_admin/auditor/accountant, own cluster for cluster_head, own store for store_manager, own records for field_officer/farmer, none for agronomist) and `scope_filters(actor, ScopeColumns(...), visibility=...)` returning SQLAlchemy filters (tenant first; a missing column or unset cluster/store fails closed). `user_scope(actor)` is the `user` table binding; farmers/visits/khata reuse it with their own `ScopeColumns` and can widen visibility per entity (agronomists read crop data).
- **Routes**: `/v1/health`, `/v1/auth/otp/send|verify`, `/v1/auth/refresh|logout` are `PUBLIC`; `/v1/me` requires any of the ten roles. New `apps/api/farmerapp/users/` (minimal WC-011 slice): `GET /v1/users` (owner, director, cluster_head, auditor, tenant_admin; cluster heads see their own cluster; keyset cursor pagination `?cursor=&limit=` from `apps/api/farmerapp/api/pagination.py` — opaque base64 of `(created_at, id)`, `limit` 1..200, `400 invalid_cursor`), `GET /v1/users/{id}` (same roles within scope, or the user themselves via `x-self`), `PATCH /v1/users/{id}` (owner, director, tenant_admin: `name`, `role`, `status`, `store_id`, `cluster_id`; `null` clears store/cluster; empty or unknown fields → 422). Out-of-scope or other-tenant ids are `404 not_found`. `UserOut` gains `created_at`.
- **Auth change**: a disabled account presenting a valid access token now gets `401 user_disabled` (+ `WWW-Authenticate: Bearer`) instead of 403, so clients drop the session and re-login (login/refresh still answer `403 user_disabled`). Console and mobile switch on the `code`, not the status, so no client change.
- **Seed** `apps/api/farmerapp/jobs/seed.py`: tenant `fcc` now has all ten roles (`+919000000001..10`), plus second tenant "Green Fields" (`gfl`, `+919100000001..10`). `SeedResult.tenants` lists both; idempotent.
- **Contract**: `apps/api/openapi.yaml` regenerated (`x-roles`/`x-public`/`x-self`, 401/403/404/400 problems, `PageOut_UserOut_`, `UserUpdate`). `problem_responses()` moved to `farmerapp/api/errors.py` for reuse.
- **Docs**: `apps/api/README.md` "Authorisation" section; progress rows FA-002, SEC-006, WC-011, SEC-028.

Design decisions and assumptions:
- Role denial (403, logged) happens before any query; record scope (404) after. A field officer asking for a colleague's record gets 403 (role does not permit reading others), a cluster head asking for a user outside their cluster gets 404 (role permits, scope hides).
- SPEC 2.6 has no accountant column; accountant is treated as tenant-wide read (finance across stores). Recorded here so it can be narrowed.
- `PATCH /v1/users/{id}` does not yet require re-auth (SEC-028) or write audit rows (FA-006); it logs `user_updated` with the changed field names only. Disabling a user does not revoke their refresh family yet (WC-011 forced logout); their next API call is already rejected.
