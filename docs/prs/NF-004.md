## What changed

All in `apps/mobile/packages/core` (nothing under apps/api, infra, .github or apps/console).

- **`lib/src/photo/photo_processor.dart`** — `PhotoProcessor.process(bytes, {captureTime, location, config})` runs `processPhotoSync` on a background isolate (`compute`). Steps: decode (JPEG/PNG; malformed input → `PhotoDecodeException`), bake EXIF orientation, resize so the long edge ≤ 1280 (`Interpolation.average`; never upscales), convert to 8-bit RGB, write a fresh EXIF block (`DateTime`, `DateTimeOriginal`, `DateTimeDigitized`, `OffsetTime`/`OffsetTimeOriginal` = `+00:00`, GPS `VersionID`/`LatitudeRef`/`Latitude`/`LongitudeRef`/`Longitude` as D/M/S rationals), encode JPEG q80 4:2:0, SHA-256. Hard cap 300 KB: q80 → q70 → q60, stopping at the first that fits; `ProcessedPhoto.quality` and `withinBudget` record the outcome. `captureTime`/`location` fall back to the input EXIF when omitted. `ProcessedPhoto.toJson()` = `{width, height, size_bytes, sha256, quality, within_budget, exif: {taken_at, lat, lon}}` (the API's `exif_time` / `exif_point`). `PhotoProcessor.readExif(bytes)` reads it back. `PhotoLocation`, `PhotoExif`, `PhotoProcessorConfig` are plain immutable values.
- **`lib/src/photo/photo_quality.dart`** — `OnDeviceQualityModel` interface (`evaluate(bytes) → PhotoQualityResult`); default `LaplacianQualityModel` (off the UI thread): grayscale copy at 320 px, variance of the 4-neighbour Laplacian (`blurScore`), mean luminance (`brightness`). `PhotoQualityConfig` defaults `blurThreshold 40`, `darkThreshold 0.15`, `analysisEdge 320`. Result carries `isBlurry`, `isTooDark`, `tipKey` (`photo.tip.blurry` / `photo.tip.dark` / `photo.tip.ok`; dark wins over blurry), `isAcceptable`, JSON. `PhotoQualityCheck.evaluate(bytes, {model})` / `evaluateSync`.
- **`lib/src/photo/chunked_upload_planner.dart`** — `ChunkedUploadPlanner.plan(bytes, {chunkSize = 256 KB, lastAckedChunk = -1})` → `ChunkedUploadPlan` (`fileSha256`, `totalBytes`, `chunks[index, offset, length, sha256]`, `pendingChunks`, `nextChunk`, `isComplete`, `uploadedBytes`, `withAck(i)` never moving backwards, `slice(payload, chunk)`, `toJson`/`fromJson` v1).
- **Widgets** — `lib/src/widgets/photo_review_card.dart` `PhotoReviewCard` (thumbnail or placeholder, "Photo n of m" / "Check your photo", `1280 × 960 px`, `186 KB`, quality badge checking/ok/blurry/dark, tip line, Retake + Use photo as 48 dp `AppButton`s, Use enabled only for an acceptable result; tokens only, Sunlight via `app.tint`/`borderWidth`). `lib/src/widgets/photo_tip_text.dart` `CoreLocalizations.photoTip(key)`. `CameraGuideOverlay` gains `tipKey`: lights "hold steady" for blurry, "good light" for dark, shows the retake line (`tipMessageKey`); static rendering unchanged (existing goldens untouched).
- **i18n** — 13 keys (`photoReviewHeading`, `photoReviewTitle`, `photoQuality{Ok,Blurry,Dark,Checking}`, `photoTip{Blurry,Dark,Ok}`, `photoRetake`, `photoUse`, `photoSizeKb`, `photoDimensions`) in en, te, kn, hi, mr; generated localisations regenerated.
- **Deps** — `image ^4.10.1` (decode/resize/encode/EXIF), `crypto ^3.0.7` (SHA-256) in `packages/core/pubspec.yaml`; workspace lock updated.
- **Design** — `design/components/PhotoReviewCard.md`, `design/components/CameraGuideOverlay.md` (tipKey prop, states), `design/screens/A41.md`, `design/screens/F22.md`.
- **Docs** — progress rows NF-004 (done), NF-003 / FM-004 / DX-001 / FA-015 (what now exists, what is left).

Design decisions and assumptions:
- EXIF is written with `package:image` and verified by decoding the output (DateTimeOriginal, offset, GPS refs and D/M/S round-trip to 1e-5°), so no separate DB column is needed for the metadata; the same values are also returned in `ProcessedPhoto.exif` for the upload payload, which is what the API stores. `Rational` is not exported by the package; values are built through `IfdValueRational(n, d).toRational()`.
- The JPEG decoder of `package:image` already applies EXIF orientation; `bakeOrientation` is still called when a tag survives, and the output carries no orientation tag.
- 4:2:0 chroma (what phone cameras produce) keeps a textured 1280×960 frame at ~193 KB; 4:4:4 would be ~40% larger. `Interpolation.average` (area sampling) is used for the downscale: it gives a cleaner result and a smaller file than linear (198 KB vs 272 KB on the 4000×3000 test image).
- The 300 KB cap is best effort: a frame of pure sensor noise stays above it even at q60 (`withinBudget == false`); the photo is still usable and the chunked upload just needs more chunks.
- Blur thresholds are calibrated on the synthetic set only (sharp ≈ 245–330, radius-3 blur ≈ 90 accepted, radius-6 blur ≈ 17–20 rejected). They live in `PhotoQualityConfig` and will be re-tuned on the labelled M6 corpus; the TFLite classifier replaces the heuristic behind the same interface.
- EXIF stamps without an offset (typical camera output) are read as device local time; our own output always writes UTC with `+00:00`.
- Farmers are never location-tracked (FA-010): the farmer app passes no `location`; the agent app passes the on-duty fix.
