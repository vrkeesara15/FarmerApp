## What changed

- **Migration 0003** `apps/api/alembic/versions/0003_rls_roles.py` (backward compatible: no column changes; the FA-001 API already binds the tenant per request):
  - roles `farmerapp_app` (runtime, DML only, `NOBYPASSRLS`), `farmerapp_migrate` (owner/DDL group, the migrating role becomes a member), `farmerapp_auth` (NOLOGIN owner of the login lookups) — created when missing, so the same migration works on compose, CI and Cloud SQL;
  - least privilege: `REVOKE CREATE ON SCHEMA public FROM PUBLIC`, `USAGE` + DML on owned tables + default privileges for future tables/sequences for the app role, nothing on `alembic_version`, functions not executable by `PUBLIC` by default;
  - `app_current_tenant()` = `NULLIF(current_setting('app.tenant_id', true), '')::uuid`; `ENABLE` + `FORCE ROW LEVEL SECURITY` and policies `tenant_isolation` (`USING`/`WITH CHECK tenant_id = app_current_tenant()`; `id` on `tenant`) and `maintenance` (`TO farmerapp_migrate USING (true)`) on `tenant`, `user`, `otp_challenge`, `refresh_token`;
  - `auth_find_user_by_phone(text)` → `(user_id, tenant_id)` and `auth_find_refresh_token(text)` → `(token_id, tenant_id)`: `SECURITY DEFINER`, fixed `search_path`, owned by `farmerapp_auth` (column-level `SELECT` through its `auth_lookup FOR SELECT` policy), executable by the app role only. The FA-001 placeholder `app.bypass_rls` is gone.
- **Reusable helper** `apps/api/farmerapp/db/rls.py`: `enable_rls(table, tenant_column)` / `disable_rls` for migrations, `rls_statements`, `role_statements`, `schema_privilege_statements`, `tenant_function_statements`, and `rls_violations(conn, tables)` — the single definition of "covered" used by the meta-test.
- **Session** `apps/api/farmerapp/db/session.py`: `set_tenant` (transaction-local `set_config`), `clear_tenant`, `bound_tenant`, `tenant_scope(session, tenant_id)` (restores the previous binding, also after errors), `job_session(tenant_id)`; `set_bypass_rls` removed. `get_current_user` binds the token's tenant before loading the user, so a mismatched `tid` is `401 unauthenticated`.
- **Auth** `otp.py` / `tokens.py`: `resolve_login_tenant` / `find_user_by_phone` and `find_refresh_token` go through the lookup functions, bind the tenant, then read under RLS; `OtpService.verify` resolves the phone's tenant (`tenant_id=` for non-login purposes); the delivery-check payload carries `tenant_id`; scheduled auth tasks run without bypass.
- **Seed** `jobs/seed.py`: fixed tenant ids (`demo_tenant_id(slug)` = uuid5) so each tenant is seeded inside its own `tenant_scope`; `make seed` runs as the app role.
- **Settings / wiring**: `DATABASE_URL` (app role) + new `MIGRATION_DATABASE_URL` (owner; Alembic env uses it; prd refuses identical URLs). `docker/postgres/initdb/10-roles.sql` (+ `COPY` in the Dockerfile) creates the `farmerapp_app` login on fresh volumes; `make db-roles` (called by `make db` / `make up`, which now `--build`) re-applies it on existing volumes. `docker-compose.yml` api service, `.env.example`, `ci-api.yml` (asyncpg URLs for both roles, role sanity check after start) updated.
- **Terraform** `infra/modules/sql`: verified SEC-011 (`ipv4_enabled=false`, `private_network`, `ssl_mode="ENCRYPTED_ONLY"`, `cloudsql.iam_authentication=on`, `google_sql_user` of type `CLOUD_IAM_SERVICE_ACCOUNT` for api/worker/jobs) and documented the one-time `GRANT farmerapp_app / farmerapp_migrate TO <iam users>` step in `main.tf` and `infra/README.md`. No resource changes; `check-infra` green.
- **Docs**: ADR 0003, `apps/api/README.md` "Tenant isolation", progress rows.

Design decisions and assumptions:
- No bypass switch at all. The only cross-tenant reads are two id-returning lookups a NOLOGIN role owns; the app role cannot `SET ROLE` to it, cannot alter roles, cannot change function ownership (all tested).
- `FORCE ROW LEVEL SECURITY` plus an explicit `maintenance` policy for the migrate role: the owner can disable RLS anyway, so the policy grants nothing new but keeps dev (compose owner is a superuser) and Cloud SQL (owner is not) identical for backfills.
- A deleted account still resolves its tenant so `verify` can consume the challenge and answer `user_not_found` inside that tenant (unchanged FA-001 behaviour).
- Fixed demo-tenant ids replace the slug lookup (a cross-tenant read) in the seed.
- Follow-ups (noted in progress.md): dedicated `migrate` service account in Terraform (the migrate job runs as the jobs SA today) and reading IAM credentials for `DATABASE_URL` in Cloud Run (`DB_IAM_AUTH` is still a placeholder); WC-014 tenant picker for a phone present in several tenants.
