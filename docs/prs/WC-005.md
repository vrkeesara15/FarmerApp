## What changed

**Migration `0014_catalog_writes`** (`down_revision = "0011"`, branch label `catalog`; the orders and payments branches also start from 0011, the parent merges heads). Expand-only:
- `label_claim.supersedes_id` (FK to `label_claim`), `retired_by`, `retired_at`;
- the `(tenant, sku, crop, pest)` unique constraint becomes the partial unique index `uq_label_claim_approved` (`status = 'approved' AND deleted_at IS NULL`) so draft / retired versions coexist with at most one approved version;
- `btree_gist` and the exclusion constraint `ex_price_list_no_overlap` (no overlapping live ranges per tenant + SKU + store, NULL store = tenant default). Seed data already satisfies it.

**API (`farmerapp/catalog/`)** — new modules `write_router.py` (mounted under the existing `/catalog` router, no `app.py` change), `write_schemas.py`, `service.py`, `prices.py`, `csv_io.py`, `recommendable.py`, `errors.py`.

| Route | Roles | Notes |
|---|---|---|
| `POST /v1/catalog/products`, `PATCH /products/{id}` | owner, director, tenant_admin | GST slab 0/5/12/18/28 %, HSN 4/6/8 digits (422 `validation_error` with field), 409 `product_exists`, 409 `version_conflict` |
| `POST /v1/catalog/skus`, `PATCH /skus/{id}` | owner, director, tenant_admin | 409 `barcode_exists` (per tenant) |
| `GET /v1/catalog/barcode/{code}` | owner, director, tenant_admin, cluster_head, store_manager, accountant, field_officer | POS scan; priced for `store_id` or the caller's store |
| `GET /v1/catalog/crops`, `/pests?crop_id=` | every role | pests of the crop + polyphagous |
| `GET /v1/catalog/stores` | price-list readers | store manager / accountant: own store |
| `POST /v1/catalog/label-claims` | owner, tenant_admin, agronomist | draft; 422 `claim_category_invalid`, 422 `pest_not_for_crop`, 409 `claim_duplicate`, 404 |
| `PATCH /v1/catalog/label-claims/{id}` | owner, tenant_admin, agronomist | draft edited in place; approved -> new draft version (`supersedes_id`); retired -> 409 `claim_retired` |
| `POST /v1/catalog/label-claims/{id}/approve` | **agronomist only** | records `approved_by` / `approved_at`; retires the superseded version in the same transaction; 409 `claim_not_draft` / `claim_duplicate` |
| `POST /v1/catalog/label-claims/{id}/retire` | agronomist, owner, tenant_admin | records `retired_by` / `retired_at` |
| `GET /v1/catalog/label-claims/{id}/history` | owner, tenant_admin, agronomist | versions newest first |
| `GET /v1/catalog/label-claims?status=draft\|approved\|retired\|all` | every role | non-maintainers always get approved only (tenant_admin joins agronomist / owner as maintainer) |
| `GET /v1/catalog/recommendable?crop_id=&pest_id=` | every role | wraps `recommendable_skus` |
| `GET /v1/catalog/price-lists?store_id=&at=&sku_id=` | owner, director, tenant_admin, cluster_head, store_manager, accountant, auditor | tenant default when no store |
| `PUT /v1/catalog/price-lists` | owner, director, tenant_admin | bulk upsert keyed by SKU + `effective_from`, all or nothing; 422 `price_above_mrp`, 409 `price_overlap`, both with `rows: [{index, sku_id, code, conflicting_id?}]` |
| `POST /v1/catalog/import/products` | owner, director, tenant_admin | CSV, dry run by default, row-level report, nothing written on any error; idempotent re-import |
| `POST /v1/catalog/import/label-claims` | owner, tenant_admin, agronomist | drafts only (never approves); changed approved claim -> new draft version |
| `GET /v1/catalog/export?kind=products\|label_claims` | owner, director, tenant_admin, agronomist, auditor | streamed CSV, same columns as import; audited `catalog.export` |

Import had to be two routes rather than one `POST /import {kind}`: each route declares one role set (SEC-006 matrix), and the two kinds have different writers.

**The guardrail.** `recommendable_skus(session, *, tenant_id, crop_id, pest_or_disease_id) -> list[RecommendableSku]` returns only SKUs with an approved, not retired, not deleted claim for exactly that crop and pest, on an active SKU of an active product, carrying the claim's dose per acre, dose per 15 L tank, PHI, PPE and safety text; own brand first, then efficacy tier. `assert_sku_recommendable(...)` raises `SkuNotRecommendable` (422 `sku_not_recommendable`) otherwise. **Not yet wired into order capture**: `farmerapp/orders` belongs to the concurrent orders branch; FA-020 must call `assert_sku_recommendable` wherever it sets `order_line.label_claim_id`.

**Audit.** Every mutation goes through the ORM, so FA-006 writes `product.*`, `sku.*`, `label_claim.*` and `price_list.*` rows automatically (the approval row carries the agronomist as actor and `status: approved` in `after`).

## Tests

- `tests/catalog/test_writes.py` — write roles, GST slabs and HSN lengths, duplicate product, version conflict, audit row; SKU barcode uniqueness per tenant, POS lookup; claim draft -> agronomist approval (owner / tenant admin / director get 403), approval audit, field validation, category vs problem type, pest crop scope, duplicate approved claim, edit of an approved claim = new version, approving it retires the old one, history, retire is final, `status=all`, cross tenant, reference lists.
- `tests/catalog/test_recommendable.py` — property-style over 12 seeded random claim sets (draft / approved / retired / deleted claims, inactive or deleted SKUs, inactive products, other crop, other pest): the result is sound (never a SKU without a matching live approved claim) and complete, ranked own brand then tier; other tenant never leaks; retiring removes the SKU immediately; `assert_sku_recommendable` rejects draft, retired, wrong SKU / crop / pest / tenant.
- `tests/catalog/test_price_lists.py` — upsert default + store rows, read back with `store_id` / `at`, `price_for` picks them up, update by `effective_from`, price above MRP per row (all or nothing), four overlap shapes, overlap inside a batch, close-then-open in one batch, validation, scope, the exclusion constraint backstop.
- `tests/catalog/test_import.py` — dry run by default, apply, idempotent re-import, update; row-level errors (GST, HSN, category, MRP, taken / duplicate barcode, pack unit) with nothing written; bad header; export round-trips and is audited; claims import as drafts only, updates the open draft, versions an approved claim; per-kind roles.
- `tests/authz/test_matrix.py` — fixtures for the 13 new operations with path params or bodies (`world` now exposes `product_id`, `sku_barcode`, `claim_id`, `pest_id`); the collection check skips JSON parsing for the CSV export (the leak check still runs).
- `tests/catalog/test_read_api.py` — tenant admin now sees drafts (claim maintainer).
