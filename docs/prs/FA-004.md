## What changed

### Mobile (`apps/mobile`)

- **ARB**: `packages/core/lib/l10n/app_{te,kn,hi,mr}.arb` fully translated (short, farmer-friendly; script names identical everywhere); `app_en.arb` gains `settingsLanguage` and `@key.description` notes where the English is ambiguous (Provisional, Credit, Scouting, Wear, Pack, Sunlight, brand names). `flutter gen-l10n` untranslated report is empty and `tool/check.sh` now fails if it is not.
- **Settings persistence** (`packages/core/lib/src/state/settings.dart`): `SettingsStore` (`InMemorySettingsStore`, `KvSettingsStore` over the Drift `kv` table), `settingsOverrides(store)` loads before `runApp`, `SettingsNotifier` writes every change; `parseSupportedLocale` ignores unknown stored codes. `packages/core/lib/src/db/open_database.dart`: `openAppDatabase()` (lazy file DB via `path_provider`), `openInMemoryDatabase()`, `appDatabaseProvider`. Both `main.dart` files bootstrap the DB + settings.
- **LanguagePicker**: each tile is now fully in its own language (script name + "Listen" text button in that language, English-name caption in the UI language); 144 dp tiles; two explicit accessibility nodes per tile (tile and speaker) instead of one merged InkWell node. Goldens regenerated (`language_picker_{light,sunlight}.png`).
- **LanguageSettingTile** (new core widget) and **A63 / F70 shells** (`apps/{agent,farmer}/lib/screens/settings_screen.dart`, routes `/settings` and `/me`): language row opens a bottom sheet with the picker; Sunlight switch. Both drive `settingsProvider`. The remaining A63/F70 rows (sync now, log out, notifications, consent, delete account) come with their own IDs.
- **String lint**: rules moved to `apps/mobile/lib/string_lint.dart` (workspace-root package) and strengthened: `Text('..')` / `Text("..")`, `label:`, `tooltip:`, `hintText:`, `helperText:`, `errorText:`, `labelText:`, `semanticsLabel:`, `semanticLabel:`; letters-only rule; `// i18n-ignore` on the same or previous line; `// i18n-ignore-file`; generated paths skipped. `test/string_lint_test.dart` (13 tests, `package:test`) runs from `tool/check.sh` together with `dart analyze lib test tool`.
- Deps: `path_provider` (core); `test` (workspace root dev). `sqlite3` ships its own native library, so no `sqlite3_flutter_libs`.

### Console (`apps/console`)

- **`lib/i18n.ts`**: tiny locale store (`setLocale`, `getLocale`, `subscribeLocale`, `initLocaleFromStorage`, `localeInitScript`), `useLocale()` / `useT()` via `useSyncExternalStore` (server snapshot English → hydration safe), `LOCALE_OPTIONS` with literal script names, `LOCALE_STORAGE_KEY`. `t()` keeps its signature for server components and metadata. `<html lang>` is stamped before hydration and on every switch; `globals.css` already maps `:lang(te|kn|hi|mr)` to the Noto script fonts and the +15% line height, so the page re-fonts without reload.
- **Every client component** (19 ds components, `ThemeToggle`, `ConsoleShell`, `LoginForm`) uses `const t = useT()`; server-rendered copy moved into small client components (`PlaceholderPage`, `LoginHeader`, `SkipLink`) so headings switch live. Metadata (browser tab) stays English.
- **TopBar**: profile button opens a `role="menu"` with a language section (five `menuitemradio` items in their own script, `lang` attribute per item, current one checked) and an optional sign-out item (`onSignOut`; replaces the unused `onProfileClick`). Escape / outside click / selection closes it. No dedicated language screen (SPEC 13.4).
- **Messages**: `messages/{te,kn,hi,mr}.json` translate every `en.json` key (142 each); `en.json` gains `language.*`.
- **`scripts/lint-strings.mjs`** accepts explicit files/directories so it can be spawned on fixtures; `scripts/lint-strings.test.ts` proves it catches raw JSX text and attributes and passes `t()`, punctuation and `i18n-ignore`.
- Playwright: new smoke test switches to Telugu from the profile menu, checks the H1 and nav in Telugu, `html[lang=te]`, persistence across reload, then Hindi and back to English.

## Decisions / notes

- Console first paint for a returning non-English user is English for one render (server HTML), then the persisted language is applied post-hydration; `lang`/font are already right from the inline script. A cookie-based server locale is a follow-up if the flash is noticed.
- Mobile: when nothing is stored, `MaterialApp.locale` is `null` so Flutter resolves the device locale against the five supported ones (English otherwise); the picker still asks explicitly on first run.
- Translations are machine-drafted by the build loop; NF-008 requires review by a native speaker before pilot (human gate, tracked in `docs/progress.md`).
