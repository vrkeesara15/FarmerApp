# A61 Travel allowance

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. From Me. Route `/me/travel`.
Requirements: FA-023 (daily km from the on-duty track, capped; expense claims with a receipt photo), NF-004 (image budget), FA-025 (offline), FA-005 (voice on the claim note), VA-E07 (the server compares a vehicle claim with the tracked km).

Implementation: `apps/mobile/apps/agent/lib/screens/field/travel_screen.dart` (`TravelScreen`, `AddExpenseSheet`) over `travelStatementProvider(month)` (`FieldRepository.watchTravel`, the `kv` cache merged with the queued `travel_claim` rows). `refreshTravel` pulls `GET /v1/travel/statement?month=YYYY-MM`.

## VV-006: which km these are

Under the three totals a caption (key `travel-km-source`) says whether the month is final: `travelKmProcessed` when every day carries the server's processed km, `travelKmEstimated` while any day still has an open duty session (`TravelDayOut.open_session`). Such a day's row carries the same note as its subtitle (key `travel-day-estimate-<date>`), ahead of the cap warning. The officer is paid on the processed figure, so the screen never shows a running estimate as if it were the settled one.

## Layout (top to bottom)

1. AppBar `travelTitle`; OfflineBannerLive; FAB `travelAddClaim` (key `travel-add-claim`).
2. `fieldAsOf(time)` caption.
3. Three StatTiles: km after the cap (key `travel-km-total`), `travelTaTotal` (key `travel-ta-total`), `travelPayable` (key `travel-payable`).
4. `travelKmByDay`: one row per day (key `travel-day-<date>`) with the date, `travelDayKm(km)` and the day's allowance; a capped day carries `travelCapped(cap)` in warning colour.
5. `travelClaimsTitle`: one card per claim (key `travel-claim-<id>`) with type and amount, its status (`travelClaimStatusQueued|Submitted|Approved|Rejected`), the officer's note and any decision note.

## Add expense (bottom sheet)

Type chips (`claim-type-fuel|bus|other`), amount in rupees (key `claim-amount`, stored as integer paise), receipt photo through the NF-004 pipeline (key `claim-take-photo`; `claim-receipt-ready` once captured), and a `VoiceTextField` note (`claim-note`, mic `claim-note-mic`). "Done" (key `claim-save`) refuses a claim with no amount (`travelClaimAmountRequired`) or no receipt (`claim-receipt-missing`), then queues:

* the receipt as a resumable upload (`travel_receipt` purpose);
* a `travel_claim` create whose `receipt_uri` is the `upload:<id>` placeholder, so the op waits for the upload.

## States

| State | Behaviour |
|---|---|
| Loading | Spinner |
| No statement, no queued claim | EmptyState `travelEmpty` / `travelEmptyHelp` (key `travel-empty`) |
| Day over the cap | `travelCapped(cap)` and the capped km |
| Queued claim | Shown first, `travelClaimStatusQueued` |
| Decided claim | Approved / not approved with the cluster head's note |
| Offline | Cached statement, queued claims, `travelClaimQueued` toast |
| Sunlight | Black text, 2 dp borders |
