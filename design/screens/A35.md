# A35 Group meeting

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. From Me → Farmer meetings. Routes `/meetings` and `/meetings/{id}`.
Requirements: FA-027 (group session with attendance by farmer OTP or QR scan, attendance list linked to farmers), VV-003 (village meeting point geofence), FA-025 (offline), FA-005 (voice on the topic).

Implementation: `apps/mobile/apps/agent/lib/screens/field/meetings_screen.dart` (`MeetingsScreen`, `NewMeetingSheet`, `MeetingScreen`) over `meetingsProvider` / `meetingProvider(id)` (`FieldRepository.watchMeetings`, the `farmer_meeting` and `meeting_attendance` sync entities).

## List (`/meetings`)

AppBar `meetingsTitle`, FAB `meetingNew` (key `meeting-new`), one card per meeting (key `meeting-<id>`) with the topic, village and date, and either `meetingAttendees(count)` or `meetingClosed`. Empty: `meetingsEmpty` / `meetingsEmptyHelp` (key `meetings-empty`).

**New meeting** sheet: village chips (key `meeting-village-<id>`) and a `VoiceTextField` topic (`meeting-topic`, mic `meeting-topic-mic`); `meetingStart` (key `meeting-create`) queues a `farmer_meeting` create with the current fix as `checkin_point` — the server evaluates the meeting-point geofence exactly as it does a `meeting` visit, so an out-of-fence meeting is rejected on sync rather than blocked on the phone.

## Detail (`/meetings/{id}`)

1. Topic, village and time; `fieldPendingSync` while the create is queued.
2. While open: `meetingAddByOtp` (key `meeting-add-otp`) and `meetingAddByQr` (key `meeting-add-qr`).
3. `meetingAttendees(count)` (key `meeting-attendee-count`) and one row per attendee (key `attendee-<farmerId>`) with the method icon, the name and either the time or `fieldPendingSync`.
4. `meetingFinish` (key `meeting-finish`), or `meetingClosed` (key `meeting-closed`) once closed.

**OTP** needs connectivity (like FA-016): pick the farmer, `POST /v1/meetings/{id}/attendance/otp`, then the six-digit code in an `OtpInput`. Offline it says `meetingOtpNeedsNetwork` (key `meeting-otp-offline`) and points at the QR.

**QR** works offline: the scanner reads the farmer app's `farmerapp://attendance?token=<jwt>` (a bare JWT is accepted too); `parseAttendanceQr` refuses anything else with `meetingQrInvalid` (key `meeting-qr-invalid`). The scan time travels with the op and the server validates the signed token against it.

A farmer attends once: a repeat is dropped on the device and the server returns the first row.
