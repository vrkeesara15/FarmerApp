# A05 Location and data disclosure

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. Shown once after A04 OTP (first run) and again from A10 "Review policy" whenever the server publishes a newer `location_policy` version.
Requirements: FA-011 (first-run disclosure with explicit acceptance stored with the policy version), VV-010 (in-app acceptance references the HR policy version), VV-009 (Play prominent disclosure for background location), NF-009 / NF-010 (plain language, read-aloud, 48 dp targets).

Implementation: `apps/mobile/apps/agent/lib/screens/onboarding/disclosure_screen.dart` (`DisclosureScreen`), state in `packages/core/lib/src/duty/location_policy_controller.dart` (`locationPolicyProvider`). Routes `/onboarding/disclosure` (onboarding) and `/home/policy` (review).

## Purpose

Tell the officer, before any location is ever read, what Mitra records, when, why and who sees it, and record the explicit acceptance (version, text hash, timestamp, device) both locally and on the server. **The DutyToggle stays disabled until this version is accepted.**

## Layout (top to bottom)

1. AppBar `consentTitle` ("Your location and data"); no back button during onboarding.
2. Intro line `disclosureIntro`.
3. When an older version was accepted: warning box `disclosureUpdated` (key `disclosure-updated`).
4. Four point cards (icon in a primary-tinted circle + body text, 48 dp icon well): `consentPoint1` what is collected (location), `consentPoint2` only while on duty (schedule), `consentPoint3` why: travel allowance and visit credit (rupee), `consentPoint4` who can see it (eye).
5. Caption `disclosureVersion(version)` ("Policy version 2026-09-v1").
6. Tertiary buttons: `consentReadAloud` (speaker; no TTS yet — shows `comingSoon`), `consentPolicyLink` ("Read the full policy") opening a draggable bottom sheet (key `policy-sheet`) with `policySheetTitle`, the version and the full text — the server's text in the app language when it sent one, else the bundled ARB translation `locationPolicyText` of the same version.
7. Bottom bar: primary AppButton `consentAgree` ("I agree", key `disclosure-agree`), disabled until the persisted state is loaded.

## Data

| Field | Source |
|---|---|
| Current policy | `GET /v1/policies/location` cached in `kv` `policy.location.current`; bundled `2026-09-v1` copy (`bundledLocationPolicyEnglish`, identical to `design/copy/location_policy_en.md`) until the first successful fetch |
| `text_hash` | `sha256(text_en.strip())` — same formula on the API |
| Acceptance | `kv` `policy.location.acceptance` `{policy_key, version, text_hash, accepted_at, device_id, app_version}` and a queued `policy_acceptance` create op with the same fields |

## Behaviour

- "I agree" → `LocationPolicyController.accept()` → onboarding continues to A06; from A10 the screen pops and the toggle is enabled.
- Newer version from the server (`refresh()` on app start when online) → `accepted` false → A10 shows the blocked toggle with "Review policy" → this screen with the "updated" box.
- Server `policy_not_accepted` on a duty start → acceptance forgotten locally, A10 notice, toggle blocked again.
- Offline first run works: the bundled copy has the same version and hash the API expects.

## States

| State | Behaviour |
|---|---|
| Loading persisted state | "I agree" disabled |
| First run | Four points, agree → A06 |
| Newer version | "updated" warning, version caption shows the new version |
| Sheet | Full text scrolls; drag handle; tap outside closes |
| Sunlight | Black text, 2 dp borders, no tinted containers |

## Accessibility

Body copy ≥ 16 sp, every icon paired with text, buttons ≥ 48 dp, read-aloud button present on the screen (audio arrives with the TTS work), full text available in the five languages.
