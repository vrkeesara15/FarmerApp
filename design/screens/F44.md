# F44 Alerts

Surface: Farmer app "Kisan" (Android, 360x800 dp), Light and Sunlight themes.
Requirements: FM-009 and FM-005 F27, with NF-002 and NF-009. Derived from SPEC 13.3 ("F44 Alerts list", "F27 Result updated notification state") and SPEC 2.4 FM-009.

Implementation: `apps/mobile/apps/farmer/lib/screens/advisory/alerts_screen.dart` (route `/alerts`), `widgets/advisory_widgets.dart`.

## Purpose

What is spreading in the farmer's district right now, how bad it is, what to look for in their own field, and what to do about it. The F27 "your crop check was updated" card sits at the top of the same list, because it is the other thing that needs the farmer's attention.

## Components used

| Component | Notes |
|---|---|
| AppBar | `alertsTitle` |
| F27 card | `cropDoctorUpdatedTitle` + the problem name -> F24-F28 result (`alerts-diagnosis-<id>`) |
| Alert card | Warning pictogram, problem name in the farmer's language, crop and district (`alert-<id>`) |
| SeverityChip | `alertSeverityHigh` / `Medium` / `Low`, each with its own icon and colour |
| Chips | `alertGrowsCrop` when one of their plots has the crop, `alertFarmersAffected(n)`, `alertWeekOf(date)` |
| Symptom checklist | `alertLookForTitle` and two to four unchecked boxes for the problem type, always ending with "Walk your field and look at 10 plants" |
| AudioButton | Reads the problem, the crop and the whole checklist (`audio-f44_alert`) |
| Actions | `alertCheckCrop` -> F20 crop doctor (`alert-check-<id>`), `alertSeeProducts` -> F30 store (`alert-shop-<id>`) |
| Dismiss | `alertDismiss` -> the alert is hidden on this phone (`alert-dismiss-<id>`) |
| AsOfLabel | "Updated ..." / "Offline. Saved on ..." |

## Severity

`GET /v1/alerts` sends counts, not a severity. The app derives one so the list can be sorted and coloured:

| Severity | Rule |
|---|---|
| High | cases >= 3 x the district baseline, or 10 or more farmers affected |
| Medium | cases >= 2 x the baseline, or 5 or more farmers affected |
| Low | anything else the outbreak rule raised |

Most severe first, then the most recent week.

## Data fields shown

| Field | Source |
|---|---|
| Alerts | `GET /v1/alerts` cached as `kisan.cache.alerts` (district level only — no farm location, AN-014) |
| Dismissed | `kisan.cache.alerts_dismissed` on this phone; a refresh does not bring a dismissed alert back |
| Updated crop check | Local `diagnosis` rows with `update_unseen` (F27) |

## States covered

| State | Behaviour |
|---|---|
| Loaded | Alerts, most severe first |
| Farmer grows the crop | "You grow this crop" chip |
| Dismissed | Hidden, and stays hidden across refreshes and restarts |
| Offline | Banner, the cached list with "as of" |
| Nothing | `alertsNone` + `alertsNoneHelp` |

## Not built

The symptom checklist is per problem **type** (pest, disease, deficiency, weed), not per problem: the alert payload carries no symptom list. A follow-up should send the corpus's `visible_symptoms` for the problem so the checklist is specific.

## Accessibility and literacy

Every icon carries a word, targets are at least 48 dp, and the checklist is read aloud in the farmer's language, because "what to look for" is the part that must work without reading.
