# F04 Consent

Surface: Farmer app "Kisan" (Android, 360x800 dp), Light and Sunlight themes.
Requirements: FM-002 (P0) with NF-009, NF-010. Derived from SPEC 13.3 (F04), 13.1 components and SPEC 2.4 / 7.

Implementation: `apps/mobile/apps/farmer/lib/screens/consent_screen.dart` (route `/consent`), shown after F03 until the data consent is on record.

## Purpose

Two separate consent cards in plain words in the chosen language, each with its own read-aloud button. "Use my data to give crop advice" is required to continue; "Send me offers and tips" is optional and can be withdrawn at any time in F70. Two decisions.

## Components used

| Component | Notes |
|---|---|
| SpokenText | Intro `kisanConsentIntro` with an `AudioButton` (`f04_intro`) |
| ConsentCard (data) | Required badge, `consentDataCardTitle` / `consentDataCardBody`, notice `kisanConsentDataNotice`, `AudioButton` `f04_data` reading title + body + notice, switch "I agree" (`consent-data`) |
| ConsentCard (offers) | Optional badge, `consentOffersCardTitle` / `consentOffersCardBody`, notice `kisanConsentOffersNotice`, `AudioButton` `f04_offers`, switch (`consent-marketing`) |
| AppButton | Primary "Continue", disabled until the data card is on; hint `kisanConsentDataNeeded` above it while off |
| OfflineBanner | When offline |

## Data fields shown

| Field | Source | Example |
|---|---|---|
| Decisions | Local switches | data on, offers off |
| Language | Current locale | `te` |
| Consent version / channel | Set by the server: tenant `consent_version`, `channel: app` for the farmer role | `2026-09-v1`, `app` |

## Actions and navigation

| Action | Result |
|---|---|
| Toggle a card | Local state only |
| Continue | `POST /v1/farmers/{id}/consents` for `data` (granted) then `marketing` (granted or refused) with the language; offline both are queued as `consent_record` creates in the outbox and sent on the next sync (start / reconnect). Then F05 (first time) or F10 |
| Read aloud | `AudioPrompt.play` with the card text in the current language |

## States covered

| State | Behaviour |
|---|---|
| Default | Both off, Continue disabled with hint |
| Offline | Banner; Continue queues the decisions ("Saved. We will send it when you are online.") |
| Refused by the server | "Could not save. Try again." |
| No voice for the language | Speaker shows "Audio unavailable" (disabled) |

## Accessibility and literacy

Every icon is paired with a text label; targets are at least 48 dp; body text 16 sp or larger; the key instruction has an `AudioButton` next to it (NF-009: device TTS in the chosen language behind the `AudioPrompt` seam, "Audio unavailable" when the phone has no voice for it). No text input (NF-010). At most two decisions on the screen.
