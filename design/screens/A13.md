# A13 Notifications inbox

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. From the Home AppBar bell and from Me. Route `/inbox`.
Requirements: FA-007 (push with in-app inbox), FA-004 (the server sends i18n keys, never text), FA-025 (offline).

Implementation: `apps/mobile/apps/agent/lib/screens/field/inbox_screen.dart` (`InboxScreen`) over `inboxProvider` (`FieldRepository.watchInbox`, the `notification` sync entity). `refreshInbox` pulls `GET /v1/notifications` on open. `NotificationCopy` (core) maps each row's `kind` and `body_key` suffix to the app's own copy.

## Layout (top to bottom)

1. AppBar `inboxTitle`; `inboxMarkAllRead` action (key `inbox-mark-all-read`) while anything is unread.
2. OfflineBannerLive.
3. `inboxUnread(count)` caption when unread > 0.
4. One card per row (key `inbox-item-<id>`), unread ones tinted with the primary container:
   * leading icon per kind (beat, order, credit, travel, flag, duty, diagnosis, visit, generic);
   * title `NotificationCopy.title`, body `NotificationCopy.body`, then the IST timestamp;
   * tap: marks read through the outbox and follows `deepLinkFor(route)`.

## Deep links (`deepLinkFor`, router.dart)

| Server route | App route |
|---|---|
| `/visits/{id}`, `/visits/{id}/confirm` | the same path (A31 / A32) |
| `/orders/{id}` | the same path (A57) |
| `/diagnoses/{id}` | `/scouting/{id}` (A43) |
| `/credit-approvals/{id}` | `/orders` (A57 list) |
| `/flags/{id}` | `/me/flags` (A62) |
| `/travel/claims/{id}` | `/me/travel` (A61) |
| `/beat/{date}` | `/beat` (A11) |
| `/duty` | `/home/day` (A12) |
| anything else | `/inbox` |

The same function routes an FCM tap, so push and inbox always land on the same screen.

## States

| State | Behaviour |
|---|---|
| Loading | Spinner |
| Empty | EmptyState `inboxEmpty` / `inboxEmptyHelp` (key `inbox-empty`) |
| Unread rows | Tinted card, primary icon, badge on Home and on the Me tab |
| All read | No "mark all read" action |
| Offline | The cached rows render; read receipts queue |
| Sunlight | Black text, 2 dp borders |

## Push (FA-007)

`PushService` (core, `packages/core/lib/src/push/`, shared with the farmer app) is the seam; `FirebasePushService.create()` (agent) returns `NoPushService` when Firebase is not configured, so the app builds and runs with push off. `PushController` registers the token after login (`POST /v1/devices/me/push-token` through `FieldPushRegistry`), refreshes the inbox on a foreground data message, routes a tap through `deepLinkFor`, and clears the token on logout and on a remote wipe.

## Copy keys

`inboxTitle`, `inboxEmpty(Help)`, `inboxMarkAllRead`, `inboxUnread`, `navInbox`, `notifBeatPlanReady*`, `notifOrderStatus*`, `notifCreditApproval*`, `notifTravelClaim*`, `notifFlag*`, `notifDutyAutoEndedBody`, `notifDiagnosis*`, `notifVisitConfirm*`, `notifGeneric*`.
