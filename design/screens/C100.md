# C100 Reports and scheduled exports

Surface: Web console (1440x900, responsive check 1024x768), Light and Dark. Route `/reports` (SideNav "Reports and exports"). Every staff role may open it; the API checks each resource's own roles. Schedules: owners, directors, tenant admins, auditors, accountants, cluster heads, store managers.
Requirements: WC-013 (exports of every list resource + scheduled reports), SEC-028 (step-up), NF-013 (consent records export).

Implementation: `apps/console/components/growth/ReportsView.tsx` over `GET /v1/exports/resources`, `POST /v1/exports`, `GET /v1/exports`, `GET/POST /v1/report-schedules`, `PATCH/DELETE /v1/report-schedules/{id}`. Cron wording: `cronSummary()` / `describeCron()` in `lib/exports.ts`.

## Layout

Header, then tabs (`?tab=`): **Run an export**, **Past exports**, **Scheduled reports**.

### Run an export

1. What to export (only the resources the caller may export), Format (the resource's own formats: CSV / Excel / XML), **Run export**.
2. The **current AN-011 filters** from the URL are shown verbatim ("from=2026-08-01, to=2026-08-31, store=…") or "No filters — the export covers everything in your scope."; the resource's columns are listed underneath.
3. Note: "An export needs a fresh one-time code (step-up) and is recorded in the audit log. At most 100,000 rows per export."
4. Step-up dialog on the first run; API errors (`export_resource_unknown`, `export_format_unsupported`, `export_filters_invalid`) surface under the controls.

### Past exports

The caller's own exports newest first: resource, format, rows, size, run at, and a **Download** link. Above the table: "Links are signed and expire 15 minutes after they are issued."

### Scheduled reports

1. Table: name, resource, recipients, **Runs** (the human-readable cron — "Every Monday at 08:00 IST"), next run, Active / Paused chip, Edit and Delete.
2. Editor dialog (step-up on save): name, resource, recipients (one email per line), a cron **preset** (Every Monday 08:00 IST / Every day 08:00 IST / 1st of every month 08:00 IST) and the raw cron field, with the live summary underneath. Validation (`validateSchedule()`): name >= 3 characters, a resource, at least one valid email, a cron we can read.
3. Delete dialog: "Nobody will receive this report again. This cannot be undone."
4. Cron is always presented in IST — an expression the console cannot describe is shown verbatim as "Cron */5 * * * * (IST)" rather than mis-described.
