# A64 Sync details

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight themes. Reached from A63 Profile and settings (Me tab) through the sync row, and from the SyncStatusPill on A10 Home.
Requirements: FA-025 (offline-first sync with conflict resolution), NF-002 (72 h offline), NF-003 (outbox with idempotency keys, resumable uploads, backoff). Derived from SPEC 13.2 "A64 Sync details (pending items, failed items with retry)".

Implementation: `apps/mobile/packages/core/lib/src/widgets/sync_details_screen.dart` (`SyncDetailsScreen`, exported from `package:farmerapp_core`), driven by `syncDetailsProvider` over `SyncEngine.watchDetails()`; the agent route is `/settings/sync` (`AppRoutes.syncDetails`).

## Purpose

Tell the officer, in one place, what has not reached the server yet and why, and give them the two actions that matter: "Sync now" and "fix and retry" for items the server rejected. Nothing here is required for daily work — capture keeps working offline and syncs on its own (periodic every 15 minutes, immediately when signal returns).

## Layout (top to bottom)

1. AppBar, title `syncDetailsTitle`.
2. Status card: SyncStatusPill (synced / pending n / failed / syncing), last sync line (`syncLastSync(time)` in IST `DD-MM-YYYY HH:mm`, or `syncNeverSynced`), and when the last attempt failed on transport: `syncTransportError` in warning colour plus `syncNextAttempt(time)` as a caption. Primary AppButton `syncNow` (spinner while syncing).
3. Empty state (only when nothing is queued or failed): EmptyState with cloud-done icon, `syncAllDone` / `syncAllDoneHelp`.
4. "Needs attention (n)" section (`syncFailedSection`), heading row with a tertiary `syncRetryAll` button; one card per rejected item: error icon, title `syncItemTitle(action, entity)` ("New farmer", "Edited farm"), the server's error detail (or `syncRejectedDefault`), and two medium buttons `actionRetry` (secondary, refresh icon) and `syncDiscard` (tertiary). Buttons wrap on narrow widths.
5. "Waiting to sync (n)" section (`syncPendingSection`), with `syncPhotoUploads(n)` caption when photos are still uploading; one card per queued op: schedule icon (photo icon while `syncWaitingForPhoto`), title, `syncSavedAt(time)`.

## Components used

| Component | Notes |
|---|---|
| SyncStatusPill | Same pill as A10; `syncing` variant added with FA-025 |
| AppButton | Primary "Sync now"; secondary Retry; tertiary Discard / Retry all |
| EmptyState | Cloud-done icon, "Everything is synced" |
| ErrorState | Only if the details stream itself fails |
| OfflineBanner | Shown by the app shell above the screen while offline (`OfflineBannerLive`) |

## Data

| Field | Source |
|---|---|
| Status | `SyncStatus` from outbox + uploads counts and the running flag |
| Last sync | `sync_states.last_sync_at` |
| Transport error / next attempt | `sync_states.last_error`, `next_attempt_at` (backoff 1 s → 5 min, jittered) |
| Pending items | `outbox` rows in `queued` / `sending`, push order |
| Failed items | `outbox` rows in `rejected` with `last_error {code, detail}` |
| Photo uploads | `uploads` rows in `pending` / `uploading` (count) and `failed` |

## States covered

| State | Behaviour |
|---|---|
| Never synced, nothing queued | "Not synced yet" + empty state |
| Pending only | Pill "Pending n", list under "Waiting to sync (n)" |
| Photo still uploading | Item shows "Waiting for the photo to upload"; caption "Photos uploading: n" |
| Rejected items | Pill "Sync failed", "Needs attention (n)" with error detail; Retry requeues the same op_id (after the user edits the item the edit folds into that op); Discard removes the op (a discarded create removes the optimistic local row) |
| Transport failure (offline, 5xx, timeout) | Pill stays "Pending n"; card shows "Could not reach the server…" and the next automatic attempt; "Sync now" ignores the backoff window |
| Syncing | Pill "Syncing…", button spinner; the run is shared, a second tap does not start another |
| Conflict | Not shown as failed: the server won and the local row was replaced; the item disappears from the list |
| Sunlight | Black text, 2 dp borders, no tinted containers (theme-level) |

## Accessibility

Every card has a semantics label "title, subtitle"; icons never carry meaning alone; all buttons ≥ 48 dp targets (medium AppButton) with text; counts are in the section headings, not only in colour.
