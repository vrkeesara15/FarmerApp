# A06 Permissions explainer

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. After A05, before A07.
Requirements: FA-010 (foreground location service), FA-012 / FA-015 (in-app camera), VV-007 (prompt notification), VV-009 (Play policy: in-app rationale before the "Allow all the time" system page).

Implementation: `apps/mobile/apps/agent/lib/screens/onboarding/permissions_screen.dart` (`PermissionsScreen`) over `PermissionGate` (`permissionGateProvider`; `PermissionHandlerGate` in the app, `FakePermissionGate` in tests). Route `/onboarding/permissions`.

## Layout (top to bottom)

1. AppBar `permissionsTitle`; intro `permissionsIntro`.
2. One card per permission (key `perm-<name>`): icon, title, reason, status chip (`permGranted` / `permDenied`) and a secondary medium button `permAllow` (or `permOpenSettings` when permanently denied):
   - `location` — `permLocationTitle` / `permLocationBody`
   - `backgroundLocation` — `permBackgroundTitle` / `permBackgroundBody` (**disabled until foreground location is granted**; Android then shows its own "Allow all the time" page)
   - `camera` — `permCameraTitle` / `permCameraBody`
   - `notifications` — `permNotificationsTitle` / `permNotificationsBody`
3. Bottom bar: primary `actionContinue` (key `permissions-continue`) → A07. Continuing without a permission is allowed; the duty toggle asks again when needed.

## States

| State | Behaviour |
|---|---|
| Not asked | No chip, "Allow" |
| Granted | Green border, check chip "Allowed", no button |
| Denied | "Not allowed" chip, "Allow" again |
| Permanently denied | "Open settings" (opens the app's system settings page) |
| Asking | Button spinner |

## Accessibility

Reasons in plain language, icons paired with text, 48 dp targets, no permission is requested without its card being visible first.
