# A57 Order success

Surface: Field agent app "Mitra", Light and Sunlight, 360x800.
Requirements: FA-020 (order reaches the store queue; stock reserved), FA-021 (invoice share), ST-005.

Implementation: `screens/orders/order_screen.dart` over `orderViewProvider` / `orderPaymentsProvider`. Route `/orders/:id`.

## Layout

1. Header: `orderPlacedTitle` (key `order-placed`), `orderQueuedTitle` + `orderQueuedHelp` (key `order-queued`) or `orderRejectedTitle` (key `order-rejected`); farmer · time · pickup / delivery.
2. Rejection box (key `order-rejection-<code>`): `orderInsufficientStock` + `orderShortLine(product, available, requested)`, `orderSkuNotRecommendable`, else the problem detail; action `orderEditAndResend` → A51 with the shortfalls.
3. Status timeline (key `order-timeline`, steps `order-step-<status>` with times from the server history): placed → stock reserved → packed → ready → handed over / delivered; cancelled pill.
4. Summary: lines (server price once synced, else estimate), `orderSubtotal` / `orderTax` / `orderTotal` or `orderTotalEstimate`, `orderInvoiceNo`.
5. Payments list (mode, A59 state, amount; opens A53 / A54 / A56).
6. Bottom: `orderShareInvoice` (key `order-share`) — enabled only online with an invoice (signed PDF link from `GET /v1/invoices/{id}/pdf` through the share sheet); reason `orderShareOffline` / `orderShareNoInvoice`; `orderCollectPayment` (A55) or `paymentDone`.

## Behaviour

Money fields are the server's once the op is applied (FA-025 server wins); the invoice id arrives as `invoice_id` on the order when the API exposes it (follow-up in docs/prs/FA-020-mobile.md).

Every state has an offline banner (`OfflineBannerLive`); strings are ARB keys in all five languages; money via `formatInr`.
