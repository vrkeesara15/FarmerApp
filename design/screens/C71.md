# C71 Flag detail

Surface: Web console, Light and Dark. From C70 "Open flag"; route `/flags/[id]`.
Requirements: WC-010, VA-002 ("evidence renders in WC-010"), VA-004 (P1: summary box shown empty), VA-005 (officer explanation thread), SPEC 6.1 state diagram.

Implementation: `apps/console/components/flags/FlagDetailView.tsx`, `EvidenceMap.tsx` (next/dynamic, client only) + `EvidenceMapLeaflet.tsx` (Leaflet 1.9, OpenStreetMap raster tiles, `NEXT_PUBLIC_MAP_TILE_URL` override; vector circle markers, polygons outlined in the primary colour). Data: `useFlag` (`GET /v1/flags/{id}`), `useTransitionFlag` (`POST .../transition {to, note}`), `useCommentFlag` (`POST .../comments {body}`), `useAssignFlag` (`POST .../assign {user_id}`).

## Layout

1. "Back to the inbox" link.
2. Header card: severity, status, rule id + version; title (h1); Owner, Watchers (names), SLA (live `SlaTimer` + due time IST), Subject, Raised (time + mode inline / event / batch), Escalation level, Resolved (time + by) and the resolution note when resolved.
3. Actions (`flag-actions`) — only moves in both the SPEC 6.1 diagram and the server's `allowed_transitions` (`lib/flags.ts availableActions`), reviewer roles only:
   - open: "Start review" (note optional)
   - in review: "Data is valid" (-> resolved_valid, counted false positive), "Data corrected" (-> resolved_fixed), "Escalate" (-> escalated, destructive)
   - escalated: "Data corrected", "Action taken" (-> resolved_action)
   Each opens a dialog with help text and a note; resolving or escalating needs the note (client check + API 409 `invalid_transition`).
4. Reassign (owner, director, auditor, cluster head, tenant admin; unresolved flags): reviewer select + "Reassign".
5. "Automated summary — verify evidence" box (`ai-summary`, dashed info border, bot icon): "not available yet" until VA-004 ships.
6. Evidence grid: Map (points and polygons from `evidence.map`; "No locations" when empty), Records (type badge, name linked to `/farmers/{id}` for farmers and `/field-team/{id}` for users — `lib/flags.ts RECORD_ROUTES`, summary fields, id), Photos (thumbnails from `signed_url`, click -> dialog with expiry time; "Photo unavailable" without a signed URL), Metrics (key / value table).
7. Discussion: comments oldest first; the subject's explanations (`is_subject_explanation`) have an info left border, tinted background and the badge "Explanation from the person flagged"; review comments are neutral. Composer "Add a comment" / for the subject "Explain what happened" + "Send explanation"; closed once resolved.
8. History (newest first) from `events`: raised and assigned, "{actor} moved it from In review to Escalated" with the note in quotes and the VA-006 label ("Counted as a false positive" / "true positive"), reassignments, SLA escalations.

## States

Loading skeletons; 404 / error -> ErrorState; 403 -> ForbiddenState; field officer (subject) sees ids-only records, no actions, and can explain while open.
