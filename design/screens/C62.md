# C62 Diagnosis quality

Surface: Web console (1440x900, responsive check 1024x768), Light and Dark. Route `/agronomist/quality` (sub-nav "Diagnosis quality"). Agronomists, owners, directors, tenant admins, auditors.
Requirements: AN-007 (diagnosis quality), DX-006 (review SLA), DX-011 (nightly evaluation). The sibling model-release view (DX-012) is the next sub-nav entry, `/agronomist/models`.

Implementation: `apps/console/components/agronomist/QualityView.tsx` over `lib/hooks/mlops.ts` -> `GET /v1/diagnoses/quality?days=`. M7 **replaced** the M6 browser-side computation (`lib/diagnosis-quality.ts`, deleted): every figure is now the server summary, so console and marts agree.

## Layout

1. Header ("Server figures for the last 30 days (AN-007)."), agronomist sub-nav, owner read-only note.
2. Period select (7 / 30 / 90 days); the header count follows it.
3. Four KpiCards: **Diagnosis requests**, **Answered by corpus** (`corpus_share`), **Escalation rate**, **Reviewed within 24 h** (`review.sla_rate`, footer "151 of 168 reviewed within 24 h").
4. Three panels: **Answered by source** (corpus / LLM / agronomist / no answer bars), **By status** (confirmed, provisional, corrected, out of scope, queued), **Review SLA** ("Average 9.4 h · median 7.1 h", "5 open, 2 overdue").
5. **Top unknowns** (crop · out-of-scope reason or "LLM could not choose", count) and **Latest evaluation (DX-011)**: run time, model name and version, cases, top-1 accuracy, change in points, accuracy per crop, and a warning note when the run alerted ("Accuracy dropped past the alert threshold; agronomists and owners were notified").
6. No evaluation yet -> "No evaluation run yet. The nightly job needs the labelled held-out set in the corpus bucket."

## States

Loading: four KpiCard skeletons (the first announces). Error: `QueryError` (403 -> the no-access state). Empty: zero counts render as zeros; `notAvailable` ("Not available") replaces a null rate.

## Copy keys

`quality.title`, `quality.subtitle`, `quality.days`, `quality.daysOption`, `quality.requests`, `quality.answeredByCorpus(+Help)`, `quality.escalation(+Help)`, `quality.reviewSla`, `quality.reviewTitle|reviewWithin|reviewAvg|reviewOpen`, `quality.bySource`, `quality.byStatus`, `quality.statusLabel.*`, `quality.topUnknowns`, `quality.unknownsHelp|unknownRow|unknownReason|unknownsEmpty`, `quality.evaluation.*`, `quality.nav.*`.

## Tests

`e2e/growth.spec.ts` "C62: diagnosis quality comes from the API, with the latest evaluation" (sources, statuses, review panel, unknowns, evaluation accuracy per crop, period switch); `e2e/agronomist.spec.ts` owner read-only test.

# C62 (model releases) — DX-012

Route `/agronomist/models`. Agronomists, owners, directors, tenant admins read; **agronomists and owners decide** (step-up, audited).

Implementation: `apps/console/components/agronomist/ModelReleases.tsx` over `GET /v1/models/releases`, `GET /v1/models/on-device/current`, `POST /v1/models/releases/{id}/decision`.

1. **Current approved version** card: model name and version, "Approved 19 Sep 2026", the SHA-256 the apps verify.
2. Releases table: version, status chip (Candidate / Approved / Rejected / Retired), built at, evaluation cases, top-1 accuracy, change in points, and for a candidate the Approve / Reject buttons (Approve is disabled without an evaluation run — the API answers 409 `evaluation_missing`).
3. Decision dialog: note, the step-up reason line, confirm. Approving retires the current version; every app downloads the new file and verifies its SHA-256.
4. A candidate with no evaluation raises a warning note above the table.

Copy keys `models.*`. Tests: `e2e/growth.spec.ts` "DX-012: approving a model release needs step-up".
