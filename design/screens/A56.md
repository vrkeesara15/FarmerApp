# A56 Credit sale with limit check

Surface: Field agent app "Mitra", Light and Sunlight, 360x800.
Requirements: FA-021 (credit / khata), ST-007.

Implementation: `screens/payments/credit_screen.dart` over `paymentViewProvider` (`PaymentView.creditBlock`). Route `/payments/:id/credit`.

## Layout

1. Queued (offline): `creditQueued`.
2. Approval needed (`credit_limit_exceeded`): `creditNeedsApprovalTitle` / `creditNeedsApprovalBody`, amount, `creditLimit`, `creditBalance`, `creditShortfall`, pill `creditSentToClusterHead`.
3. Actions: `creditCheckAgain` (requeues the same op and syncs; `creditStillPending` / `creditOfflineCheck`), `creditUseCash` (drops the credit op, A55).
4. Approved: `creditApprovedTitle` + `collectionStateOnKhata`; `paymentDone` → A57.

## Behaviour

The approval request is created server-side by the rejected op and kept; once a cluster head approves it the same order goes through once. Officers cannot list approvals, so the re-check is the resend.

Every state has an offline banner (`OfflineBannerLive`); strings are ARB keys in all five languages; money via `formatInr`.
