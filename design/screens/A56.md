# A56 Credit sale with limit check

Surface: Field agent app "Mitra", Light and Sunlight, 360x800.
Requirements: FA-021 (credit / khata), ST-007.

Implementation: `screens/payments/credit_screen.dart` over `paymentViewProvider` (`PaymentView.creditBlock`). Route `/payments/:id/credit`.

## Layout

1. Queued (offline): `creditQueued`.
2. Approval needed (`credit_limit_exceeded`): `creditNeedsApprovalTitle` / `creditNeedsApprovalBody`, amount, `creditLimit`, `creditBalance`, `creditShortfall`, pill `creditSentToClusterHead` (`credit-sent`); once the request's decision arrives in the change feed (`credit_approval_request`, `creditApprovalStateProvider`): `creditApprovedSending` (`credit-approved-sending`) or `creditRejectedByClusterHead` (`credit-rejected`).
3. Actions: `creditCheckAgain` (manual fallback: requeues the same op with `credit_approval_request_id` and syncs; `creditStillPending` / `creditOfflineCheck`), `creditUseCash` (drops the credit op, A55).
4. Approved: `creditApprovedTitle` + `collectionStateOnKhata`; `paymentDone` → A57.

## Behaviour

The approval request is created server-side by the rejected op and kept. It reaches the officer through the sync change feed (scoped to the requesting officer and the store's staff). When a pull brings it `approved`, the sync engine requeues every op rejected for that request with `credit_approval_request_id` and pushes it in the same run, so A56 flips to "on khata" without a tap; a rejection is shown and "Collect cash instead" stays.

Every state has an offline banner (`OfflineBannerLive`); strings are ARB keys in all five languages; money via `formatInr`.
