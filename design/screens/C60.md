# C60 Agronomist review queue

Surface: Web console (1440x900, responsive check 1024x768), Light and Dark. SideNav "Agronomist" (`nav.agronomist`, route `/agronomist`), shown to agronomists (work) and owners (read only); hidden for every other role (`lib/nav.ts` `AGRONOMIST_ROLES`). Sub-navigation: Review queue · Corpus (C61) · Diagnosis quality (C62).
Requirements: WC-006 (acceptance "correction updates farmer result and notifies farmer"), DX-005 (provenance), DX-006 (review SLA 24 h, ageing alert at 18 h), SPEC 3.4 guardrails.

Implementation: `apps/console/components/agronomist/ReviewQueue.tsx` (route `app/(console)/agronomist/page.tsx`), `Evidence.tsx` (candidates, LLM answer, provenance), `PhotoGallery.tsx`, `ReviewForm.tsx` (problem picker), `common.tsx` (`SlaBadge`, sub-nav, read-only note). Data: `lib/hooks/diagnosis.ts` `useReviewQueue` over `GET /v1/diagnoses/review-queue?crop_id=&confidence=&min_age_hours=&flagged=&cursor=`, `useReviewDiagnosis` -> `POST /v1/diagnoses/{id}/review`; problem names from `GET /v1/corpus/problems`; crop names from `GET /v1/catalog/crops`. Helpers in `lib/diagnosis.ts` (`reviewSla`, `candidateRows`, `validateReview`, `reviewBody`).

## Layout

1. Page header `queue.title` / `queue.subtitle`, sub-nav, owner read-only note (`agronomist.readOnly`).
2. Filters (`queue-filters`): Crop, Confidence, Age ("Older than 6 / 12 / 18 / 24 h" = `min_age_hours`), "Flagged only"; Clear when filtered.
3. Counts row: "5 waiting", "2 past 18 h" (danger when > 0), one badge per confidence, "Oldest first" (the API order).
4. Two columns: queue list (min 18rem) and detail panel.
   - Queue card: crop, status badge (Provisional / Out of scope / Answered), confidence band, Flagged badge, current label (local name) · district, "Waiting 19h 15m", live SLA badge.
   - Detail: heading "Crop · label", status / confidence / flagged / "Farmer asked an expert", SLA badge; photo gallery (signed URLs, thumbnails; dialog with zoom 100-400 %); farm context (crop, district, season, stage, captured time only — never farmer name, phone or id); current label or "Out of scope: reason"; model candidates table (problem, similarity 3 decimals, votes of the top 10, vote-share bar, "Corpus pick" / "LLM pick" chips) and the thresholds line "Thresholds v2: T1 0.92 · agreement 60% · floor 0.85"; the LLM answer in a dashed info box labelled **"Automated suggestion — verify"** (answer, model confidence, reasoning, visible symptoms; "not used" when the corpus answered); provenance (answer source, encoder, on-device model, LLM model, corpus version); review history.
   - Review form (agronomist only): Decision radios Confirm label (only when there is a label) / Correct label / Not diagnosable; Correct shows the problem picker (live corpus problems of the diagnosis's crop, search matches every language and the code, status chip per problem); note (required, 2000); "Add these photos to the corpus" (hidden for not diagnosable); Submit review.
   - After submit (`review-done`): "Review saved", "The farmer now sees: Zinc deficiency (khaira) (Corrected).", **"The farmer and their field officer have been notified."**, "2 photos added to the corpus as reviewed images.", "Next in queue".

## SLA badge (DX-006)

Counts from `created_at` like the API: "Review due in 5h 20m" (secondary) until 18 h; from 18 h (or when the API says `overdue`) warning colour "18 h alert · due in 4h 45m"; from 24 h danger "SLA breached 2h 30m ago" (`data-level` ok / warning / breach). Ticks every second.

## Validation

Decision required; note required; Correct requires a problem that differs from the current label ("Pick a problem other than the current label, or confirm it."). Server problems `review_invalid`, `diagnosis_not_reviewable` shown inline.

## States

Session loading skeleton; signed out -> sign-in prompt; other roles -> ForbiddenState; loading -> 4 card skeletons + panel skeleton; empty -> "The queue is clear" / filtered "Nothing matches these filters"; error -> ErrorState with retry.
