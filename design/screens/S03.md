# S03 Checkout

Surface: Field agent app "Mitra", store mode (role-gated: `store_manager`, `accountant`; `cluster_head` read-only plus S09), tablet portrait 800 x 1280 dp, Light and Sunlight. Frame: `StoreShell` (`apps/mobile/apps/agent/lib/screens/store/store_shell.dart`): at >= 700 dp a `NavigationRail` (key `store-rail`; Home / Sell / Orders / Stock / Credit / Day close, filtered by role) and two-pane content; below 700 dp a drawer (`store-drawer`) and the single-pane fallback. App bar: title, store switcher (`store-switcher`, when the user sees more than one store), settings (`store-settings` -> A63). `OfflineBanner` while offline; `storeReadOnlyBanner` (key `store-read-only`) for cluster heads. Loading = `Skeletons.list`; offline = `ErrorState` `store-offline` (`storeOfflineTitle` / `storeOfflineHelp`, retry); error = `ErrorState` `store-error`. Money via `formatInr` (integer paise). State in `packages/core/lib/src/store/` (`store_providers.dart`, `store_api.dart`, `store_models.dart`, `store_calc.dart`).

Route `/store/pos/checkout`. Requirements: ST-001, ST-002, ST-007.

Implementation: `apps/mobile/apps/agent/lib/screens/store/checkout_screen.dart`.

## Layout

Two panes at >= 700 dp: payment (left) and `storeInvoicePreview` (right, `checkout-preview`); phones stack cart, preview and payment.
1. `storePayWith`: `StoreModeSelector` (radio cards with the look of `PaymentMethodSelector`, which has no card-terminal option): `mode-upi_qr`, `mode-card_terminal`, `mode-cash`, `mode-credit` (credit enabled only for a known farmer).
2. Mode inputs: card -> `storeCardReference` (`checkout-card-ref`, required: `storeCardReferenceRequired`); cash -> `storeCashTendered` (`checkout-cash-tendered`) and the live `storeCashChange` (`checkout-change`), a short tender is refused (`storeCashShort`); credit -> hint `storeCreditNeedsFarmer` without a farmer.
3. Preview: `GstInvoiceView` (lines with HSN, qty, rate, GST %, amount; `storeTaxable`; CGST + SGST (`invoice-cgst|sgst`) or IGST; round-off; total; amount in words) from the server: `POST /v1/stores/{id}/pos/preview` with the sale body, asked when S03 opens and again `posPreviewDebounce` (400 ms) after a cart / buyer change. Note by state (`checkout-preview-<status>`): `ready` `storePreviewServerNote`; `loading` `storePreviewLoading`; `offline` `storePreviewOffline`; `unavailable` (refused) `storePreviewUnavailable`. Offline / refused / loading show the local estimate (`GstPreview.of`, same rule as `invoices/gst.py`) with the chip `storePreviewEstimate` (`checkout-preview-estimate`); the cash check uses the server total when it is there. The issued invoice (number) comes back with the sale and is shown on S04.
4. `storeConfirmSale` (`checkout-confirm`) -> `POST /v1/stores/{id}/pos/sales` (Idempotency-Key). States: `checkout-offline` (`storeOfflineSaleTitle` / `storeOfflineSaleHelp`; nothing is sent, the cart is kept); UPI -> `UpiQrPanel` (`checkout-upi`) shown first, `GET /v1/payments/{id}` every 3 s (`upiPollInterval`) until paid (-> S04) or failed (`upiRetry` -> `POST /v1/payments {order_id, mode: upi_qr}`); 402 `credit_limit_exceeded` -> `checkout-approval` (`storeApprovalNeededTitle`, `storeApprovalNeededHelp(shortfall)`, balance, limit, `storeCheckApproval` (`checkout-check-approval`), `storeChooseAnotherMode`), cart and `approval_request_id` kept; "Check approval" reads `GET /v1/credit-approvals?status=approved&farmer_id=`: approved -> the sale is retried with `credit_approval_request_id` (-> S04); else `checkout-approval-pending|rejected|offline` (`storeApprovalPending` / `storeApprovalRejected` / `storeApprovalCheckOffline`); other refusals -> `checkout-failed` (`storeSaleFailed(code)`).
