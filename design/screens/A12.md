# A12 My day timeline

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight. From A10 "My day" and from a `duty_auto_ended` notification. Route `/home/day`.
Requirements: VV-008 (the officer sees the same day the cluster head sees, and adds reasons for gaps), VV-007 (how each session ended), VV-006 (processed km, stops, gaps), VV-001 / VV-002 (pending / accepted points), FA-023 (the day's travel allowance), FA-005 (voice on the gap note).

Implementation: `apps/mobile/apps/agent/lib/screens/home/my_day_screen.dart` (`MyDayScreen`, `GapReasonSheet`) over `myDayProvider` (`DutyRepository.watchDay`, this phone's own duty rows) **and** `dayTimelineProvider(date)` (`FieldRepository.watchDay`, the cached `GET /v1/me/day?date=`). The local half always renders; the server half replaces the km, the track, the stops, the visit pins and brings the gaps.

## Layout (top to bottom)

1. AppBar `myDayTitle`.
2. Map (`MapPanel`, key `my-day-map`, open polyline, no corner markers, non-interactive, 200 dp) — the server's processed track when it is there, else the device's points.
3. Three StatTiles: km (key `my-day-km`), `myDayStops(count)`, `myDayVisitPins(count)`.
4. A caption saying which km this is: `myDayKmProcessed` once the server has processed the day, `myDayKmEstimated` until then.
5. Point counters: `syncPending(n)` and `syncSynced`.
6. One card per session (key `day-session-<id>`): `myDaySessionActive(start)` (green) or `myDaySession(start, end)`; subtitle `myDayKm(km) · myDayPoints(pending, accepted) · end reason` (`myDayEndReasonManual|AutoTime|AutoIdle|Forced|Rejected`).
7. `myDayGapsTitle` with `myDayManagerSeesReasons` — the officer is told, plainly, that the cluster head reads these.
8. Gaps (key `day-gap-<id>`), warning-bordered while unexplained: `myDayGapRange(start, end, minutes)`, the reason and note once given, and either `myDayGapAddReason` (key `day-gap-reason-<id>`) or a green tick. With no gaps: EmptyState `myDayNoGaps` / `myDayGapsHelp` (key `my-day-gaps`).

## Add-reason sheet (VV-008)

`myDayGapSheetTitle`, the gap's time range, a radio group of the four server reasons (`gap-reason-network|personal_break|vehicle|other`) and a `VoiceTextField` note (`gap-note`, mic `gap-note-mic`). "Done" (key `gap-save`) queues a `track_gap` op — a create the first time, an update after — and says `myDayGapReasonSaved`. It works with no network at all.

## States

| State | Behaviour |
|---|---|
| Loading | Spinner |
| No session and no server track | EmptyState `myDayEmpty` / `myDayEmptyHelp` (key `my-day-empty`) |
| Active session | Green card "Duty since 09:00", live counts |
| Ended sessions | Start – end, reason |
| Day not processed yet | Client km estimate, labelled `myDayKmEstimated` |
| Gap without a reason | Warning border and "Add reason" |
| Gap with a reason | Reason · note, green tick |
| Error | ErrorState with retry |
| Sunlight | Black text, 2 dp borders |

## Data

| Field | Source |
|---|---|
| Sessions | `duty_sessions` started in the IST day |
| Client track / km | `location_buffer` points of those sessions |
| Pending / accepted | points with `batch_id` null; `sync_docs` `location_batch` results |
| Server track, km, stops, gaps, visits, travel | `GET /v1/me/day?date=` cached in `kv` under `field.day.<date>` |
| Gap reasons | outbox `track_gap` `{reason, note}`, entity id = the gap id from `/me/day` |
