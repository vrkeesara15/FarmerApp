# C103 Audit log viewer

Surface: Web console, Light and Dark. SideNav "Audit log" (`nav.audit`) for owner, director, auditor, tenant admin.
Requirements: WC-103, FA-006, SEC-028 (export behind step-up; the export itself is audited `audit_log.export`).

Implementation: `apps/console/components/admin/AuditView.tsx`, `AuditDiff.tsx`; DS `DataTable` (optional `expandedKeys` + `renderExpanded` detail row). Data: `useAuditLogs` (infinite query, 50 per page) over `GET /v1/audit-logs`; export `GET /v1/audit-logs/export` (CSV, same filters, no paging).

## Layout

1. Filter form (`audit-filters`), kept in the URL so links can open it pre-filtered (e.g. from C102): Entity (free text with suggestions: user, device, tenant, flag, farmer, …), Entity id (id or its first characters, hex and `-`, sent as `q`), Actor (users by name), Actor role (staff roles + system), Action (exact, or a prefix ending in `.`, e.g. `user.`), From / To (IST calendar dates -> start / end of day +05:30). Apply, Clear, **Export CSV** (step-up; downloads `audit-log.csv`).
2. "Dates and times are in IST."
3. DataTable newest first: expand toggle, Time (DD-MM-YYYY HH:mm IST), Action (code), Entity + id, Actor name + role, Changed fields (up to 4 badges, "+N more").
4. Expanded row: before / after table, one row per field, changed fields first with before tinted red and after tinted green, unchanged ones muted; "not set" for fields missing on one side; nested values as compact JSON. Metadata: IP address, device, user agent, trace id.
5. "Load older rows" while `next_cursor` is set.

## States

Loading skeleton rows; empty -> `audit.emptyTitle`; entity id / date order validated before applying; error -> ErrorState (403 -> ForbiddenState).
