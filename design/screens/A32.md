# A32 Farmer confirmation

Surface: Field agent app "Mitra", Light and Sunlight. Reached from A31 `visitConfirmFarmer`.
Requirements: FA-016 (OTP to the farmer's phone, push prompt in the farmer app, or QR shown to the farmer app; the visit is confirmed only after one channel succeeds).

Implementation: `apps/mobile/apps/agent/lib/screens/visits/confirm_screen.dart` (route `/visits/:visitId/confirm`); calls in `VisitFlow.requestConfirmation` / `confirmOtp` / `flushQueuedConfirmations` over `VisitConfirmApi` (`HttpVisitConfirmApi`: `POST /v1/visits/{id}/confirm/request {channel}`, `POST /v1/visits/{id}/confirm {channel: sms_otp, code}`; `FakeVisitConfirmApi` in tests). QR rendered with `qr_flutter`.

## States

| State | Content |
|---|---|
| Choose (key `confirm-choose`) | `visitConfirmIntro`; three option tiles: `visitConfirmOtp` (key `confirm-otp`, SMS icon, `visitConfirmOtpHelp`), `visitConfirmPush` (key `confirm-push`, phone icon), `visitConfirmQr` (key `confirm-qr`, QR icon) |
| OTP (key `confirm-otp-state`) | `visitConfirmOtpSent(phone_masked)` + `OtpInput` (key `confirm-otp-input`, resend → new request); wrong code → `otpInvalid` + `otpAttemptsLeft`, visit stays unconfirmed; lockout `otpLocked` |
| Push waiting (key `confirm-push-waiting`) | spinner, `visitConfirmWaiting`, `visitConfirmWaitingPush`; offline the request is kept on the device (`visit_confirmations.status = queued`, `visitConfirmQueued`) and sent when A32 next opens online |
| QR waiting (key `confirm-qr-state`) | `QrImageView` (key `confirm-qr-image`, 220 dp on white) of the signed token from the request response, `visitConfirmQrWaiting`, `visitConfirmQrHelp`, `visitConfirmExpires(min)` |
| Confirmed (key `confirm-done`) | success icon, `visitConfirmed`, `visitConfirmedVia(channel)`, primary `visitConfirmContinue` |
| Messages (key `confirm-message`) | `visitConfirmNeedsNetwork` (OTP offline), `visitConfirmQrNeedsSync` (QR offline), `visitConfirmNotSynced` (check-in not on the server yet), `visitConfirmAlready`, `visitConfirmRefused` |

Footer: tertiary `visitConfirmChooseAnother` (key `confirm-another`) and secondary `visitConfirmLater` (key `confirm-later`) → back to A31.

## Rules

- SMS OTP and QR need the network now (the request sends the code / issues the token). The API has no sync op for requesting a confirmation; an offline push request lives only in the local table until it is sent.
- The QR token is stored on the device only (`visit_confirmations.token`), never in an outbox payload.
- Push and QR are completed by the farmer's app; the officer's screen switches to Confirmed when the pull brings `visit.confirmed_at` / the confirmation row (`visit_confirmation` is a sync entity).
- An open request (push pending / queued, QR pending with a token) is resumed when A32 reopens.
