# C61 Corpus manager

Surface: Web console (1440x900, responsive check 1024x768), Light and Dark. Route `/agronomist/corpus` (sub-nav "Corpus" under SideNav "Agronomist"). Agronomists write; owners read (the API also lets directors read, but the SideNav hides the section from them per the M6 brief).
Requirements: WC-007 (acceptance "only approved entries used in production"), SPEC 3.2 corpus entry, DX-005 (corpus version), NF-003 (chunked upload).

Implementation: `apps/console/components/agronomist/CorpusManager.tsx` (route `app/(console)/agronomist/corpus/page.tsx`), `ProblemDialog.tsx`. Data: `lib/hooks/diagnosis.ts` over `GET/POST /v1/corpus/problems`, `PATCH /v1/corpus/problems/{id}`, `POST /v1/corpus/problems/{id}/transition`, `GET/POST /v1/corpus/problems/{id}/images`, `POST /v1/corpus/images/{id}/transition`, `POST /v1/corpus/approvals`, `GET /v1/corpus/versions`; uploads through `lib/uploads.ts` (`POST /v1/uploads` purpose `corpus`, `PUT .../chunks/{i}` with `X-Chunk-Sha256`, `POST .../complete`). Workflow rules in `lib/corpus.ts` (`corpusActions`, `isEditable`, `bumpsVersion`, `servedImageCount`).

## Layout

1. Header, sub-nav, owner read-only note.
2. Production banner (`production-note`, primary container): shield icon + **"Only approved entries are used in production: approved problems with their approved images. Approving is the regulatory human gate."** and the "Corpus version 7" badge.
3. Filters: Crop, Status, Source, **"Show what production uses"** (forces status = approved; the table's "Served images" column shows approved images of approved problems only); "New problem" (agronomist).
4. Problems table: problem (local name, English below in other locales; opens the detail), crop, type, status chip (Draft warning, Reviewed info, Approved success, Retired neutral), image counts by status, served images, source, approved in version.
5. Problem detail panel: heading "Name · Crop", status, type, source, "Approved in version n"; Edit (agronomist, draft / reviewed only); workflow buttons; "locked" note for approved / retired; names in the five languages; symptoms in a chosen language; reviewed / approved / retired times, notes.
6. Images: upload form (agronomist, not on retired problems): file, stage, part (default leaf), severity, region, season, source; "Upload image" then "Uploading 40%" / "Embedding…"; grid of cards (image from the signed URL, status chip, "From a review" when added from C60, **"Embedded · siglip-base-patch16-224@2024-01"**, metadata stage / part / severity / region / season / source, per-image workflow buttons). With the production filter only approved images of an approved problem are shown.
7. Version history: v, Current badge, date, "1 problems · 1 images · 0 retired", note.

## Workflow (agronomist; owners see no buttons)

draft -> Mark reviewed / Retire; reviewed -> Approve / Back to draft / Retire; approved -> Retire; retired -> none. Approve opens a confirmation: "moves the corpus from version 7 to 8", the regulatory human gate text, "I have verified this entry" (required; confirming without it shows the gate text as an error), "Also approve the n reviewed images of this problem" (checked by default -> one `POST /v1/corpus/approvals` = one version bump), optional note, "Approve and publish". Retire confirms too (retiring an approved entry bumps the version). Toast "Corpus version is now 8".

## Create / edit dialog

Crop, pest or disease (product master, pairs with a live entry hidden), "Type: Pest" (from the pest), language switch (English / Telugu / Kannada / Hindi / Marathi) with name, symptoms (one per line) and cultural practices per language, "Missing: Kannada, Hindi, Marathi" hint, source (create only), notes. English name required. Errors `corpus_problem_exists`, `corpus_problem_invalid`, `corpus_entry_locked` inline.
