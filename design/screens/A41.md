# A41 Photo review (scouting)

Surface: Field agent app "Mitra" (Android, 360x800 dp), Light and Sunlight themes.
Requirements: FA-015 (in-app photo, EXIF + server time), FM-004 gate reused for officers, NF-004 (image budget), DX-001 (on-device quality), NF-003 (chunked upload queued from here). Derived from SPEC 13.2 "A41 Photo review (retake/use, up to 3)".

Implementation: screen shell lands with FA-015 / M6 scouting. The photo pipeline it uses exists now in `apps/mobile/packages/core/lib/src/photo/` (`PhotoProcessor`, `PhotoQualityCheck`, `ChunkedUploadPlanner`) and the card in `lib/src/widgets/photo_review_card.dart`.

## Purpose

After A40 Camera returns a frame, show the officer what will be uploaded (size and sharpness), let them retake a bad one, and collect up to 3 photos before A42 Analysing. Nothing leaves the device until "Use photo": the gate keeps bad photos off the network (SPEC 3, "the on-device step keeps bad photos off the network").

## Flow

1. A40 returns raw camera bytes + capture time + on-duty GPS fix (FA-010; no fix when off duty).
2. `PhotoProcessor.process(bytes, captureTime:, location:)` on a background isolate: orientation baked, 1280 px long edge, JPEG q80 4:2:0, EXIF `DateTimeOriginal`/`OffsetTimeOriginal=+00:00` and GPS written, SHA-256; falls back to q70 / q60 above 300 KB.
3. `PhotoQualityCheck.evaluate(processed.bytes)` (Laplacian model today, TFLite `OnDeviceQualityModel` in M6). While it runs the card is in the checking state (about 100 ms at 1280 px).
4. Card shows the result. Blurry / dark: "Use photo" disabled, tip shown, Retake returns to A40 with `CameraGuideOverlay(tipKey:)` lighting the matching tip.
5. "Use photo": bytes saved to app storage, `ProcessedPhoto.toJson()` (width, height, size, sha256, quality, exif) + `ChunkedUploadPlanner.plan(bytes).toJson()` stored on the outbox row; the visit gets the photo reference. Counter advances ("Photo 2 of 3").

## Components used

| Component | Notes |
|---|---|
| AppBar | Title `photoReviewHeading`; back returns to A40 |
| PhotoReviewCard | One per photo taken so far; the latest on top with live quality state |
| AppButton | Primary "Continue" to A42 when at least one accepted photo (label `actionContinue`); tertiary "Add another" until 3 |
| SyncStatusPill | Shows pending when the visit already has queued uploads |
| OfflineBanner | Photos queue offline; A42 shows the "queued" state |

## Data fields shown

| Field | Source | Example |
|---|---|---|
| Title | `index`/`total` | Photo 1 of 3 |
| Dimensions | `ProcessedPhoto.width × height` | 1280 × 960 px |
| Size | `ProcessedPhoto.sizeBytes` | 186 KB |
| Quality badge + tip | `PhotoQualityResult.tipKey` | Good photo / Blurry / Too dark |
| Thumbnail | `MemoryImage(processed.bytes)` | |

## States covered

| State | Behaviour |
|---|---|
| Checking | Info badge, Use disabled, Retake enabled |
| Good | Success badge, Use enabled |
| Blurry | Danger badge, `photoTipBlurry`, Use disabled |
| Too dark | Warning badge, `photoTipDark`, Use disabled |
| Over budget (`withinBudget == false`, only extreme noise) | Photo still usable; size shown honestly; upload is chunked so it just takes more chunks |
| 3 photos accepted | "Add another" hidden |
| Offline | Same; uploads queue (NF-002/NF-003) |
| Sunlight | Black text, 2 dp borders, no tinted containers |

## Accessibility

Card semantics "Photo 1 of 3, Good photo, 186 KB"; buttons 48 dp with icon + text; tip in body size; badge colour never the only signal.
