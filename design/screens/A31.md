# A31 Visit in progress

Surface: Field agent app "Mitra", Light and Sunlight. Reached from A30 after check-in and from an open VisitCard (A34 / A22 Visits tab).
Requirements: FA-015 (purpose, notes, at least one geotagged photo taken in-app — gallery disabled —, crop stage), VV-004 (score shown before check-out), FA-005 (voice input, P1: placeholder), FA-014 (rejection handling).

Implementation: `apps/mobile/apps/agent/lib/screens/visits/visit_screen.dart` (route `/visits/:visitId`) over `visitDetailProvider(id)` (`VisitRepository.watchDetail`) and `visitTickProvider` (1 s ticker; tests override `visitTickerProvider`). Score: `evaluateVisitProof` in `packages/core/lib/src/visits/visit_proof.dart` — the device twin of `farmerapp/visits/scoring.py` (30 / 30 / 20 / 10 / 10; override 15 once approved; photo within ±10 min of the window and 150 m of the check-in point; integrity fails on mock, root or drift > 300 s).

## Layout

1. AppBar `visitInProgress` + sync pill; offline banner.
2. Farmer name, purpose icon + label.
3. Sync line (key `visit-sync-state`): `visitCheckInPending` / `visitCheckInSynced`; **or** the rejection box (key `visit-rejected`, danger): `visitRejectedTitle` + `visitRejectedOutside(distance)` (from the problem's `distance_m`, falling back to the detail text) / `visitRejectedNoTarget`, secondary `visitRetryFromFarm` (key `visit-retry`).
4. Timer card: `visitTimerLabel`, elapsed `M:SS` (key `visit-timer`, display style), `visitMinDuration(min)`, `visitExpectedScore` / `visitServerScore` + `VisitScoreBadge` (key `visit-expected-score`; the server's score wins once stored).
5. `visitProofTitle` + **ProofChecklist** (key `visit-proof`): geofence (✓ inside / meeting point / approved override; ✗ `proofGeofenceOverride` or `proofGeofenceOutside`), photo (✓ `proofPhotoDone` when one in-app photo has EXIF time and point inside the window), farmer confirmed, duration (`visitDurationNeeds(min, minimum)` ticking, then `proofDurationDone`). `proofIntegrityIssue` caption when the integrity component is 0.
6. `visitPhotos` + `visitPhotoCount(n)`, `visitPhotosHelp`, thumbnails (keys `visit-photo-<i>`), then either the `PhotoReviewCard` (key `visit-photo-review`, Use / Retake with the NF-004 quality gate) or the secondary `visitTakePhoto` (key `visit-take-photo`, camera icon). **There is no gallery button, icon or text anywhere** (`CameraSource` has only `capture()`, bound to `ImageSource.camera`).
7. `visitNotesLabel`: `AppTextField` (key `visit-notes`, hint `visitNotesHint`) + disabled mic `IconButton` inside `Tooltip(visitVoiceInputSoon)` (key `visit-voice`).
8. Crop stage chips `visitCropStageLabel` (keys `visit-stage-<wire>`: sown, vegetative, flowering, fruiting, maturity, harvested).
9. Secondary `visitConfirmFarmer` (key `visit-confirm`) → A32 (disabled once confirmed); primary `visitCheckOut` (key `visit-check-out`) → A33 (disabled while rejected).

## Behaviour

| Event | Op |
|---|---|
| Photo used | processed JPEG saved, resumable upload (`purpose visit_photo`), `visit_photo` create `{visit_id, blob_uri: upload:<id>, sha256, exif_time, exif_point, taken_in_app: true, device_time}` waiting for the upload |
| Crop stage | `visit` update `{crop_stage}` |
| Notes | sent with the next A32 open / check-out as `visit` update `{notes}` (only when changed) |
| Check out | `visit` update `{checkout_at, checkout_point, notes?}` |
| Retry from the farm | new fix + pre-check; inside → the rejected create op is requeued under the same `op_id` with the new `checkin_at` / `checkin_point`; still outside → snackbar `visitRetryStillOutside(distance)` |
