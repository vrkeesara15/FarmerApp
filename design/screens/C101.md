# C101 Users and roles, device bindings, force logout

Surface: Web console, Light and Dark. SideNav "Users and roles" (`nav.users`) for owner, director, tenant admin (write) and cluster head, auditor (read). Admin sub-navigation Users · Settings · Audit log (`AdminSubNav`, by role).
Requirements: WC-011 (API acceptance "revoked user loses access within 5 min" met server-side), SEC-020, SEC-025, SEC-028.

Implementation: `apps/console/components/admin/UsersView.tsx` (`/admin/users`), `UserDetailView.tsx` (`/admin/users/[id]`), `StepUp.tsx`, `badges.tsx`. Data: `lib/hooks/admin.ts` over `GET/POST /v1/users`, `GET/PATCH /v1/users/{id}`, `POST .../deactivate`, `POST .../force-logout`, `GET .../devices`, `POST .../devices/{device_id}/bind|report-lost`; stores from `GET /v1/catalog/stores`.

## Users list

Filters: search (name / phone), role, status; "New user" for write roles. DataTable: Name (link to detail), Phone, Role, Store / cluster ("Whole tenant" when neither; clusters have no list endpoint yet and show "Cluster …c001"), Status badge, Device status (Bound / Waiting for approval / Reported lost / Unbound / No device; pending first).

New user dialog: mobile (+91), full name, role (owner role only offered to owners), app language (tenant default), store, cluster (store required for store manager / accountant, cluster for cluster head / field officer). Create runs through step-up; `phone_taken` and `invalid_assignment` show on their field.

## User detail

Header: name, status, role, phone, store / cluster, created (DD-MM-YYYY). Security actions (write roles, never on yourself): **Force logout**, **Deactivate**. Each opens a confirmation dialog that states the effect and "You will be asked for a one-time code", then step-up, then a toast.

"Role and assignment" form: name, role, status, store, cluster; role / status changes confirm first and need step-up (name / assignment save directly). Owner accounts are locked for non-owners; your own role / status are disabled.

Devices table: model + device id, platform · app version, status, last seen (IST), bound date; actions: "Bind this device" (pending / unbound; for field officers the dialog says the current phone is unbound and signed out), "Report lost" (active / pending; the app wipes on next contact).

## Step-up (SEC-028)

`useStepUp().run(call)`: on 401 `step_up_required` the dialog sends a code to the admin's phone (`/v1/auth/step-up/send`, "Enter the 6-digit code we sent to +91******3210"), verifies (`/v1/auth/step-up`), retries the call with `X-Step-Up-Token`. The 5-minute token is kept in memory only (`lib/step-up.ts`) and reused until it expires; a reload forgets it. Wrong code: inline error with attempts left; Cancel: "Cancelled. Nothing was changed."
